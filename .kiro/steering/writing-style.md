# 业务化写作与汇报风格规范

本文件定义本仓库所有文档（方案 / PRD / 汇报 / 周报）的写作风格。Kiro 在生成内容时必须遵循。

## 一、总原则：金字塔 + 数据驱动

1. **结论先行**：每一份文档、每一节、每一段，第一句话必须是结论或核心观点。
2. **数据支撑**：凡是判断都要有量化指标（百分比、金额、天数），避免"较好/较快/明显提升"这类形容词。
3. **业务语言**：站在业务方视角讲"省了多少钱、提了多少效率、解决了什么痛点"，而不是"用了什么技术"。
4. **结构对齐**：所有同类文档使用相同结构，方便跨项目对比和老板快速浏览。

## 二、汇报材料黄金结构（业务方视角）

```
1. 一句话结论          —— 老板只看这一句也能懂
2. 业务背景与痛点      —— 我们为什么要做这件事（带数据）
3. 解决方案概要        —— 一图一句话，避免技术细节
4. 进展与里程碑        —— 已完成 / 进行中 / 待启动
5. 预期收益（核心）    —— 量化：成本↓、效率↑、KPI 改善
6. 风险与依赖          —— 需要哪些资源、可能的阻碍
7. 下一步行动          —— 谁、做什么、什么时候完成
```

## 三、写作具体要求

### ✅ 推荐写法

- "本季度仓储成本下降 **12%**，主要来自波次合并算法上线后人效提升 **18%**"
- "上线后预计**库存周转天数从 45 天降至 35 天**，等同于释放 **2000 万**资金占用"
- "当前缺货率 **3.2%**，目标 **<1.5%**，差距来自补货模型未考虑促销爆发"

### ❌ 避免写法

- "效率明显提升"（多少？）
- "我们采用了微服务架构"（业务方不关心）
- "通过 API 打通了 OMS"（说"和订单系统联动"即可）
- "上线了一个新功能"（解决了什么问题？）

## 四、不同对象的语气调整

| 汇报对象 | 重点 | 语气 |
|---|---|---|
| **CEO / 业务老板** | ROI、战略、资金占用、市占率 | 极简，3 页内讲完 |
| **业务部门** | 流程改善、操作便捷性、KPI | 场景化，多举例子 |
| **财务 / 审计** | 成本、合规、对账准确性 | 严谨，数据精确到小数点 |
| **IT / 技术评审** | 架构、稳定性、扩展性 | 可使用技术术语 |

> 默认语气：**面向业务老板**，除非文档头部明确标注"技术评审"。

## 五、图表使用规范

1. **流程图**：用 Mermaid `flowchart`，节点用业务语言（如"收货""上架"，不要写"调用 inbound API"）
2. **架构图**：业务版用模块化方框图（"商品中心""库存中心"），技术版才出现"服务/数据库"
3. **数据图**：趋势用折线，构成用饼图，对比用柱状图——一图只讲一件事
4. **每张图必须有**：标题、单位、数据时间范围、数据来源

## 六、命名与版本

- 文档命名：`{项目代号}-{文档类型}-{版本}.md`，如 `WMS01-PRD-v1.2.md`
- 版本规则：v0.x 草稿 / v1.0 评审通过 / v1.x 小修订 / v2.0 大改版
- 重大评审节点打 Git Tag，便于回溯

## 七、Kiro 协作约定

- 用户给草稿/纪要 → Kiro 套结构出初稿，**第一句必须是结论**
- 用户说"业务语言改写" → 移除所有技术黑话，参照本文档"禁忌词"翻译
- 用户说"做汇报" → 默认按本文档"汇报黄金结构"输出，除非另有指定
- 用户说"加数据" → 提示用户补充真实数据，**不得编造数字**，可用 `[待填:xxx]` 占位
